# 变更摘要

## 1.5.0

### 新增 Qt 前端

- 新增功能与界面完全一致的 Qt（PySide6）前端 `codex_config_qt.py`，复用主程序的全部业务逻辑，只重写视图层
- 消除「从任务栏恢复窗口时闪一下」的问题：Tk 顶层窗口没有 backing store，恢复时先呈现后绘制，中间 1-3 帧由合成器用窗口背景色填充；Qt 的顶层窗口同时具备表面与 backing store，实测同样 8 轮最小化/恢复中 **0 帧空白**（Tk 为 8/8 闪、12/241 空白帧）
- 压平 `Canvas`、`WS_EX_LAYERED`、`WS_EX_COMPOSITED` 三种方案均已实测排除，原因与数据见 `AGENT_HANDOFF_WINDOW_BUGS.md`
- 两种前端共用同一个安装标识、安装目录和用户设置，可随时换用而不影响已有配置
- 新增 Qt 版 PyInstaller 配置与构建脚本；两个前端的产物互不覆盖
- 新增闪烁与窗口行为的测量工具集 `prototypes/`，可复现全部结论

### 无边框主窗口（最小化 / 任务栏 / 标题栏）

- 修复最小化后从任务栏恢复时同时出现 Windows 原生标题栏和自绘黑色标题栏的问题
- 主窗口在整个生命周期内保持无边框：不再在最小化时切换 `overrideredirect`，因此不会重建窗口、不会重新出现原生边框
- 最小化改为对真实顶层 HWND 调用 `ShowWindow(SW_MINIMIZE)`，进程保持存活，任务栏按钮保持不变
- 通过 `ITaskbarList::AddTab` 为无边框窗口注册任务栏按钮，正常、最小化、恢复三种状态都可见；不再依赖“隐藏再显示窗口”让 Shell 重新识别
- 修正窗口句柄解析：`winfo_id()` 返回的是 Tk 内部子窗口，任务栏与最小化相关操作统一作用于它的根祖先窗口（`TkTopLevel`）
- 补齐 `GetParent`/`PostMessageW` 的 Win32 参数类型；此前句柄被按 32 位整数截断，最小化和任务栏恢复消息实际没有生效
- 重复最小化/恢复不再改变窗口尺寸，稳定保持 `820x500`
- 拖动自绘窗口改用向顶层 HWND 发送 `WM_NCLBUTTONDOWN/HTCAPTION`，不再在鼠标移动期间高频重设 Tk 几何尺寸，修复界面破碎
- 撤回动态 Win32 边框/尺寸补偿和自定义 WndProc 方案（后者曾触发 Python GIL 崩溃），改为在初始化阶段抵消外框宽度偏差
- 保留 `WS_MINIMIZEBOX`、系统菜单和任务栏窗口样式，修复任务栏按钮无法切换显示/最小化的问题
- 恢复窗口时在同一个顶层 HWND 上原地重新应用 `WS_EX_APPWINDOW`，修复配置切换重启 Codex 后任务栏图标消失
- 主窗口不可最大化：补齐对 `SC_MAXIMIZE` 的拦截，并避免在最小化状态下误触发守卫
- 移除历史实验代码：`WM_NCCALCSIZE` 子窗口过程替换、`WS_POPUP`/`WS_EX_TOOLWINDOW` 样式切换、`<Map>`/`<Unmap>` 帧恢复逻辑
- 新增窗口生命周期自动化验证脚本（`prototypes/`）与 6 条回归用例，覆盖“不切换 overrideredirect”“最小化走 Win32”“任务栏按钮注册”等关键约束

### 界面细节

- 修复确认对话框的「是/否」按钮左右颠倒：Tk 的 `pack(side="right")` 把先创建的控件放在最右，Qt 的 `QHBoxLayout` 从左往右追加，两个工具链对「第一个」的定义相反；该差异适用于每一个右对齐按钮对
- 修正表格区域整体上移 9px：Tk 按 `linespace`、`QLabel` 按 `height()` 计算标签盒子高度，差在「每行」
- 修正 `panelHeading` 字号：角色未指定 `font-size` 时继承基础样式 9pt，而 Tk 用 8pt 粗体绘制
- 修复自动换行文本被截断在句子中间：`QLabel.setWordWrap(True)` 在祖先面板为 `QSizePolicy.Fixed` 时只按 `sizeHint()` 给一行高度
- 五页版面全部对齐，`worst |dy| = 0px`

### 构建与安装

- 修复安装版构建批处理窗口过早关闭的问题；构建完成后显示全部产物的完整输出路径，并保留窗口供用户查看
- `scripts\build.bat` 现在作为统一入口，一次生成 Tk 与 Qt 的便携版和安装版共四个资产，并输出每个资产的字节数与 SHA-256
- 三个 PowerShell 构建脚本改为显式验证解释器（同时具备 tkinter、PySide6、PyInstaller），不再信任 PATH 上的第一个 `python`——本机 PATH 上的那个没有 tkinter，构建不会报错，失败会推迟到运行期
- 修复 Qt 安装包文件名缺少连字符（`CodexConfigToolQt-Setup-…`）
- 新增 `[InstallDelete]` 段：两个前端共用同一个安装标识和目录，换前端安装时清理另一个前端的 EXE，避免留下孤儿可执行文件
- 修复 `.spec` 通配忽略规则导致 `CodexConfigTool-Qt.spec` 未被纳入版本控制的问题；该文件是 Qt 构建的必需输入，此前从新克隆的仓库无法构建 Qt 前端
- 版本号全线升到 `1.5.0`：主程序、Windows 版本资源、安装器定义、README 与发布说明

## 1.4.0

### 安装、更新与兼容性

- 新增 Inno Setup 安装包，默认按当前用户安装，不要求管理员权限
- 安装时默认创建桌面快捷方式，用户可取消；同时创建开始菜单和卸载入口
- 继续提供版本化便携版，安装、升级和卸载均不触碰 Codex 配置、API Key 或聊天记录
- 新增一键构建便携版与安装包的脚本，并对安装目录、快捷方式和敏感数据边界增加自动检查
- 修复安装包残留英文提示和桌面快捷方式助记键显示
- 修复主窗口同时出现 Windows 原生标题栏和自绘标题栏的问题
- 卸载时可选择删除或保留配置助手自身设置，并警告第三方卸载工具不要删除 Codex 本体目录
- 卸载界面改为“保留用户数据 / 完全删除用户数据”二选一；完全删除仅清理配置助手设置和 `.codex\\backups` 配置库
- 新增启动后台更新检测，并在“关于软件”中提供手动“检查更新”入口
- 检测到新版本时在“关于软件”图标右上角显示小红点，不弹窗、不静默下载或替换正在运行的 EXE；进入关于窗口后可手动前往 GitHub Release
- 更新检测改为读取 GitHub Release 页面跳转，避免匿名 REST API 限流导致 HTTP 403，且不下载完整发布页
- Microsoft Store 版 Codex 改用 Windows 应用激活接口启动，保留系统应用身份及任务栏/托盘图标注册
- 重启 Codex 时确认旧主进程完全退出，并等待 Windows Shell 清理旧托盘 GUID 后再启动，避免主窗口出现但托盘图标缺失
- Microsoft Store 版 Codex 交由 Windows Explorer 独立激活，避免 Codex 生命周期依附配置助手进程
- 配置切换启动 Codex 时读取 AppX 包清单中的真实应用 ID，优先使用与开始菜单一致的 Windows AppsFolder 入口
- 自动重启先使用不带 `/F` 的正常退出请求；退出失败时不强杀、不启动第二实例
- 启动后等待并确认新的 Codex 主进程和主窗口出现，系统入口失败时才回退到不带隐藏窗口标志的真实 EXE
- 修复 Explorer 启动成功但 Codex 固定托盘 GUID 残留导致系统托盘图标缺失的问题；Store 正式版重启前只清理 Codex 自己的通知区注册
- 自动关闭改为调用 Codex Windows 版自身注册的 `Ctrl+Q` 菜单加速键，进入与托盘“退出”相同的 Electron `app.quit()` 流程；不再使用 taskkill
- 移除左侧独立“一键重启”，双击配置统一负责应用、正常退出和重新启动；Codex 已运行且配置无变化时不会重复重启

### 配置管理与界面

- 增加 `config.toml` TOML 语法、权限字段组合及重复项目信任路径校验，发现冲突时阻止自动覆盖
- 统一项目配置目录的规范绝对路径，减少同一项目重复识别或重复请求信任
- 模型列表请求错误信息统一脱敏，避免 API Key 出现在界面或日志中；实际请求鉴权不变
- 新增“推荐渠道”页面，提供 AI Ark API 和 JM2 API 网站入口并支持默认浏览器打开
- 新增供应商模型列表获取与下拉选择，并在新增、编辑窗口保留 Model 手动输入
- 修复官方登录模式切换时删除配置文件导致聊天记录和会话状态丢失的问题
- 更新 README 的当前配置、新增与编辑配置、配置列表、官方登录、新手引导、推荐渠道、关于和赞赏界面截图
- 精简官方登录页面和确认提示，避免说明文字超出面板边界
- 修正官方登录页面说明，明确不会删除 `auth.json`、`config.toml` 或会话数据
- 官方登录与 API 配置切换改为非破坏性字段合并，不再删除 `auth.json` 或 `config.toml`
- 切换过程中保留 ChatGPT 登录令牌、会话标识、聊天记录目录、历史记录及未知配置字段
- 增加 API-A → 官方登录 → API-K 的会话保留和双文件失败回滚测试
- 当前配置页改为只读展示连接信息和启动默认模型；获取模型、下拉选择和手动输入仅保留在新增、编辑窗口
- 新增、编辑弹窗明确提示 OpenAI 原生模型无需获取列表，“获取模型”仅用于第三方 Provider
- 新手引导使用暗红色重点提示“供应商是GPT或者OpenAI模型时，无需获取模型”
- 模型列表请求只在用户主动点击后发起，并设置超时、响应大小限制、禁止跨地址重定向和错误信息脱敏
- 获取结果先保留在编辑事务中，只有点击“保存配置”或“保存修改”时才与连接信息和完整模型列表一起原子落盘；取消不修改磁盘
- 新增、编辑仅保存配置库，不立即应用或启动 Codex；移除“保存并使用/保存并应用”以统一操作入口
- 编辑当前活动配置后记录待应用状态，避免旧 live 配置反向覆盖刚保存的配置库副本
- Model 下拉按钮使用内缩的小型线条 chevron；输入框与弹窗外框统一为四边 `2px`，列表隐藏滚动条并保留滚轮、方向键和键入定位
- 配置列表双击切换扩展到整行，名称、Base URL 和行内空白均可触发
- 增加模型接口解析、鉴权请求、配置同步和事务回滚测试
- 自定义 Provider 的模型目录优先精确复用 Codex 本机原生模型元数据，未知模型继续生成兼容条目；官方 OpenAI Provider 不再使用配置助手自有目录
- 明确每个配置保存的是启动默认模型和默认推理强度；Codex 对话内临时选择不回写配置库，也不读取或修改私有对话状态
- 配置切换使用 Codex 自身正常退出流程，完全退出后保存原配置公开默认值、应用目标配置并通过 Windows 正式入口自动启动
- 修复 OpenAI 原生配置误用模型列表目录的问题；原生模型与推理强度完全交由 Codex 管理，第三方 Provider 仍保存配置助手模型目录
- 双击配置成为唯一应用和启动入口：Codex 停止时启动，有待应用修改时先应用，运行且无修改时只提示已在运行
- 配置切换失败时恢复 live 配置、配置库和待应用标记，未确认自动重启时保持零写入
- 将新增、编辑窗口状态提示合并到按钮行，移除常驻空白并缩短弹窗高度

## 1.3.0

- 一键重启优先正常关闭 Codex，避免“跟随系统”等显示设置因强制结束而回退

- 支持识别 Microsoft Store 和普通桌面安装的 Codex，只处理 Codex 桌面应用
- 优化长 API Key 的横向浏览、选择和键盘定位体验
- 按新版视觉规范统一所有 API Key 显示与隐藏图标
- 修复长 Key 越界拖选时原生与自定义逻辑冲突导致的边界字符闪烁
- README 新增一键重启截图和使用说明，交接文档同步记录重启流程约束
