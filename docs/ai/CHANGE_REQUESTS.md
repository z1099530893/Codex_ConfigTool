## BUG-005 - Windows 最小化导致配置助手退出

提出：2026-09-09
原始问题：客户反馈 v1.4.0 点击自绘标题栏的最小化按钮后，配置助手会自动退出，而不是保持在任务栏中。
状态：FIXED-BUT-CLIENT-RETEST
根因判断：此前为规避退出问题而在最小化和恢复时切换 `overrideredirect` 并重新注册任务栏样式，这会让 Windows Shell 重新创建任务栏按钮，产生图标/标题刷新和重复按钮；同时任务栏按钮没有稳定复用同一个顶层 HWND。
修复方案：保持无边框窗口和既有任务栏注册不变，使用顶层窗口自身的 HWND 调用 Win32 `SW_MINIMIZE`；恢复时不再重新注册或切换窗口框架，任务栏按钮保持稳定。
安全边界：不修改 Codex 配置、API Key、聊天记录或系统托盘对象；未执行 Git 提交、推送或发布操作。
验证：Python 语法检查、118 项标准库测试、`git diff --check` 和隔离 Tk 运行时最小化→恢复→关闭冒烟测试通过；仍需客户在实际 v1.4.0 使用环境复测任务栏恢复。
追加反馈：客户复测时发现任务栏图标点击无反应且关闭行为异常，说明最小化使用的 HWND 需要继续复用任务栏注册时的顶层句柄；同时确认希望一个脚本同时完成便携版和安装版构建。
追加修复：恢复使用 `GetParent(winfo_id()) or winfo_id()` 得到的顶层 HWND，显式注册 `WM_DELETE_WINDOW`；将 `scripts\build.bat` 改为统一入口，一次调用安装包构建流程并显示两个产物路径、保留窗口。
追加诊断与修复：上一版 `PostMessageW` 未声明 64 位 HWND 参数，导致消息句柄截断、最小化和任务栏恢复无效；已补齐 `GetParent`/`PostMessageW` 的 Win32 参数类型。
追加反馈：配置切换重启 Codex 后配置助手任务栏图标消失；主窗口显示和最小化状态下，任务栏图标与主窗口不能同时存在。
追加修复：恢复无边框窗口时在同一个顶层 HWND 上原地重新应用 `WS_EX_APPWINDOW`，不再通过 `withdraw/deiconify` 让 Explorer 重建按钮。
追加修复：改为保持正常顶层窗口，通过 Win32 样式移除原生标题栏和边框；最小化/恢复不再切换 `overrideredirect`，避免窗口和任务栏按钮分离。
追加反馈：主窗口最小化正常且任务栏图标不消失，但点击任务栏图标不能切换显示/最小化。
追加修复：隐藏边框时只移除 `WS_CAPTION` 与 `WS_THICKFRAME`，保留 `WS_MINIMIZEBOX` 等系统窗口能力。
客户反馈：上一轮恢复路径改动后重新打包出现主界面尺寸变化、拖动破碎窗口和恢复闪烁，要求撤回上一轮修改后重新实现。
追加修复：恢复恢复样式调用；同时在首次隐藏原生边框后抵消 Windows/Tk 的外框宽度偏差，固定主窗口为 `820x500`，避免拖动坐标和绘制区域错位。
客户反馈：该动态边框方案在打包版仍导致尺寸递增、闪烁和拖动破碎窗口。
追加修复：撤回动态 Win32 边框/尺寸补偿和自定义 WndProc；恢复 Tk 无边框窗口生命周期，最小化只使用 Tk `iconify()`，任务栏样式只在初始化阶段注册。
